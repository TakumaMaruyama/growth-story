# 私の競泳物語

日々の練習日誌と、自分自身の競泳物語を記録する、単一チーム向けの会員制 Web アプリです。

## 主な機能

- 管理者から案内する共通登録URLによる、保護者同意つき会員登録
- 1日1件の練習日誌（自己評価、振り返り、次回の意識、長期カラーバッジ）
- 次の大会、年間、期限つきで整理できる大会目標
- 15の問いから作る競泳物語とバージョン履歴
- 日誌・大会目標・物語更新を色分けした記録カレンダーと一覧
- 管理者による共通登録URLの共有、会員の退会・利用再開、全会員記録の閲覧
- 退会または保護者同意の撤回後も、本人は過去の記録を閲覧可能

## 現在のチーム運用

現在は1つのチームを、`ADMIN` 権限を持つ管理者が共同で管理する初期構成です。チームの新規作成、複数チームの切り替え、オーナー・ヘッドコーチ・コーチ・閲覧者といったチーム内役割、担当選手だけに限定する閲覧権限はまだありません。すべての管理者は、全会員の日誌、大会目標、競泳物語を読み取り専用で確認できます。

会員登録は次の流れです。

1. 管理者が管理画面に表示される共通登録URLを、保護者へ安全な方法で送る
2. 保護者が共通登録URLを開く
3. 保護者が選手本人の本名（姓・名）、保護者氏名、選手との関係、ログインID、パスワードを入力する
4. 表示された取り扱い内容に同意して登録する

共通登録URLは複数の保護者が繰り返し利用できます。チーム外へ転送せず、URLが意図せず共有された場合は `REGISTRATION_ACCESS_TOKEN` を更新して再公開し、以前のURLを一括で無効にします。同じ本名の再登録は表記ゆれを正規化したうえで拒否するため、登録済み・退会済みの選手は新規アカウントを作らず、管理者へ利用再開を依頼します。新規会員の本人画面には本名の「名」だけを表示し、管理画面には姓と名を表示します。既存会員の氏名は推測で分割せず、従来の表示名を維持します。

パスワードを忘れた場合は、保護者が管理者へ連絡し、管理者が本人・保護者確認後に会員一覧から選手別の再設定URLを発行します。URLは発行から2日間・1回限り有効で、再発行すると以前のURLは無効になります。再設定が完了すると、その会員の既存セッションをすべて終了します。過去の記録を引き継ぐため、新規登録し直さないでください。

登録画面では、次の内容を明示します。

> 登録時に入力する選手の本名、保護者氏名、選手との関係は、会員の識別、指導およびサービス運営のため、管理者が確認します。選手本人の画面には、本名の「名」のみ表示します。
>
> 本サービスに入力された内容（日誌、大会目標、競泳物語）は、指導およびサービス運営のため、管理者も確認できます。
>
> 退会または保護者同意の撤回後は、日誌・大会目標・競泳物語の新規入力および更新ができなくなります。過去に登録した内容は閲覧のみ可能です。利用再開には管理者による手続きが必要です。

同意欄の文言は「上記の内容を確認し、保護者として同意します」です。同意日時、保護者氏名、選手との関係、案内文の版を保存します。

「退会」と「ログイン停止」は別の状態です。退会中の会員はログインして過去の記録を閲覧できますが、日誌、大会目標、競泳物語の新規作成・更新・削除はできません。ログイン停止では既存セッションを終了し、ログイン自体を止めます。利用再開は、管理者が保護者の意思を別途確認したうえで行います。退会処理だけではアカウント、保護者同意、過去の記録を削除しないため、削除・匿名化・保持期間は別の運用として定める必要があります。

## 技術スタック

- Next.js 16 / React 19 / TypeScript
- PostgreSQL / Prisma
- カスタムセッション認証（HttpOnly Cookie、DBにはトークンのハッシュのみ保存）
- CSSによるレスポンシブ・ダークモード対応

## ローカルセットアップ

必要な環境は Node.js 20.19 以上、22.12 以上、または24以上と PostgreSQL です。対応範囲は `package.json` の `engines.node` を正とします。

```bash
npm ci
cp .env.example .env
npm run db:init
```

`.env` の `DATABASE_URL` は利用する PostgreSQL に合わせ、`REGISTRATION_ACCESS_TOKEN` には32バイトの暗号学的乱数をbase64url化した43文字の値を設定してください。

管理者アカウントを作成します。

```bash
ADMIN_LOGIN_ID=admin \
ADMIN_PASSWORD='10文字以上の安全なパスワード' \
ADMIN_DISPLAY_NAME='管理者' \
npm run admin:create
```

起動後は管理者画面の「共通の会員登録URL」を保護者へ案内します。トークンを含まない `/register` から自由にアカウントを作成することはできません。

開発サーバーを起動します。

```bash
npm run dev
```

## 品質チェック

```bash
npm run check
ALLOW_INTEGRATION_DB_TESTS=1 DATABASE_URL="postgresql://user:pass@127.0.0.1:5432/swim_story_test" npm run test:db
ALLOW_INTEGRATION_DB_TESTS=1 DATABASE_URL="postgresql://user:pass@127.0.0.1:5432/swim_story_test" npm run test:migrations
DATABASE_URL="postgresql://user:pass@127.0.0.1:5432/swim_story" npm run build
npm run audit:prod
```

`npm run check` は ESLint、Prisma Client 生成を含む型検査、ユニットテストを順に実行します。`npm run test:db` は専用のテストDBで実行し、並列レート制限、セッション上限、日誌・大会目標の競合更新、物語の同時作成を検証します。`npm run test:migrations` は一時DBを作成し、旧データを投入してから全マイグレーションを実行し、アーカイブ値の保持と連鎖削除防止を確認後に一時DBを削除します。

## データベース運用

- 開発時のマイグレーション作成: `npm run db:migrate -- --name <name>`
- 本番への既存マイグレーション適用: `npm run db:init`
- `prisma/migrations` は必ず Git で管理します
- `db:push` は試作用であり、本番デプロイには使用しません

2026年8月のマイグレーションでは、廃止した旧計測機能のテーブルをアプリから切り離し、`archived_growth_profiles` と `archived_growth_measurements` に改名して保存します。データは自動削除せず、利用者の削除に連動しないよう外部キーも `RESTRICT` に変更します。保持期間を決めたうえで削除または匿名化する場合は、暗号化バックアップと復元テストを済ませ、別の明示的な作業として実施してください。

`20260803000000_invite_registration_and_membership_status` では、既存利用者を `ACTIVE` 会員として維持したまま、会員状態、旧個別登録URL、保護者同意を追加します。既存利用者には保護者同意レコードが自動作成されないため、運用開始前に既存利用者への案内・同意確認方法を決めてください。現在のアプリは個別URLを新規発行せず、Secretの共通登録URLを利用します。旧個別URLの行は履歴として保持し、削除・再利用しません。

`20260803000300_user_real_name` では、選手の姓・名を保存するnullable列を追加します。既存会員の表示名を本名とみなしたり自動分割したりせず、新規登録された会員だけに姓・名を保存します。

同時にセッショントークンをハッシュ保存へ移行するため、適用時に既存セッションは一度無効になり、利用者は再ログインが必要です。旧バージョンとはDB互換性がないため、本番では書き込みを止めたメンテナンス時間内に `npm run db:init` と新バージョンの切り替えを連続して行い、旧バージョンへ戻さないでください。

## セキュリティ上の仕様

- 一般ユーザーの新規パスワードは8文字以上。英数字のみでも設定でき、bcryptの上限であるUTF-8 72バイト以内
- `admin:create` で作る管理者パスワードは10文字以上
- 旧仕様の長いID・72バイト超パスワードはログイン互換を維持し、旧bcrypt cost 10ハッシュは成功時にcost 12へ更新
- ログインと会員登録はDB共有型の試行回数制限を適用
- 会員登録は管理者から保護者へ案内する共通登録URLが必須。256-bitのトークンを `REGISTRATION_ACCESS_TOKEN` としてSecretに保存し、同じURLで複数の選手を登録可能
- 共通URLのトークンはURL fragment（`#access=...`）で渡し、登録ページで即座にアドレス欄から除去するため、HTTPアクセスログやRefererには送信されない
- 共通URLが漏えいした場合は `REGISTRATION_ACCESS_TOKEN` を更新して再公開し、以前のURLを一括で無効化
- 登録ページは外部サイトへ登録URLを送信しないよう `Referrer-Policy: no-referrer` を設定
- 保護者の同意日時、氏名、選手との関係、案内文の版を保存
- 選手の本名は姓・名を分けて保存し、本人向けAPIには本名全体を返さない
- 日誌・大会目標・物語の保存にも利用者単位（物語は全体上限も含む）のDB共有型レート制限を適用
- 試行回数制限はDBロックで原子的に消費し、期限切れイベントを自動削除
- Cookieは本番で `Secure` / `HttpOnly` / `SameSite=Lax`（外部リンクのGETは維持し、クロスサイトPOSTには送信しない）
- 更新APIは同一オリジンと `application/json` を検証
- リクエスト本文はストリーム読み込み中にサイズ上限を適用
- 日誌・大会目標・物語はサーバー側で型、日付、文字数、同時更新を検証
- 退会中の会員による日誌・大会目標・物語の書き込みは、画面だけでなく保存トランザクション内でも拒否
- 会員登録日時と同意内容は `users` と `guardian_consents` に保存し、退会・利用再開、ログイン状態変更は監査イベントとして保存

`TRUSTED_PROXY_IP_HEADER` には、インターネットから直接届く値ではなく、デプロイ先のリバースプロキシまたはCDNが上書き・追記するヘッダーを指定してください。`x-forwarded-for` の場合は右端の値を利用します。未設定時は安全側に倒して全リクエストを同じ送信元として制限します。

## デプロイ

1. `DATABASE_URL`、`TRUSTED_PROXY_IP_HEADER`、43文字の `REGISTRATION_ACCESS_TOKEN` をデプロイ環境の Secret に登録
2. 別環境で `npm ci && npm run check && npm run build` を完了
3. 暗号化バックアップを取得し、別DBへの復元テストを完了
4. メンテナンス表示に切り替え、アプリからのDB書き込みを停止
5. `npm run db:init && npm run db:verify` を実行
6. 新バージョンを起動し、管理者ログイン・共通登録URLのコピー・同じURLからの複数の保護者同意つき会員登録・利用者ログイン・日誌保存・大会目標保存・物語保存・退会後の閲覧専用状態をスモークテスト
7. 問題がなければメンテナンス表示を解除

マイグレーション後に失敗した場合は旧アプリだけを再起動せず、書き込み停止を維持してください。原因を修正して新バージョンを再デプロイするか、バックアップを別DBへ復元して接続先を切り替えます。

### Replit での初回公開

1. GitHub からリポジトリをインポートし、開発用の Replit Database を追加する
2. Workspace の Shell で `npm ci && npm run db:init && npm run db:verify` を実行する
3. Preview で管理者が共通登録URLをコピーし、そのURLから保護者同意つき会員登録、ログイン、日誌・物語の保存を確認する
4. Autoscale を選び、`.replit` に定義した Build / Run コマンドで公開する
5. Replit Database の Production 接続先に対して、マイグレーション履歴と `npm run db:verify` の結果を確認する
6. 管理者を作成し、最初は非公開状態で管理者ログインを確認してから Public に切り替える

現在の Replit 管理DBは、公開時に開発DBとは分離した本番DBと本番用 `DATABASE_URL` を用意します。Workspace の開発用 `DATABASE_URL` を Deployment Secret へコピーしないでください。手動設定するのは、Replit 管理DBではなく外部の専用本番DBを意図して使う場合だけです。

Deployment Secret には `TRUSTED_PROXY_IP_HEADER=x-forwarded-for` と、暗号学的乱数から生成した43文字の `REGISTRATION_ACCESS_TOKEN` を設定します。公開後は、Replit のプロキシを通った値が想定どおり取得でき、利用者間でレート制限が不必要に共有されないことを確認してください。`ADMIN_LOGIN_ID`、`ADMIN_PASSWORD`、`ADMIN_DISPLAY_NAME` は管理者作成時だけ使用し、作成後は永続的な Secret から削除します。
